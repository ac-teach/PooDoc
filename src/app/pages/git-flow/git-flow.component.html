Git Flow y Configuración de Repositorio con GitHub CLI

obligatorio

El repositorio de LibraryApp no será solamente un lugar donde almacenar el código terminado. Durante esta actividad Git debe registrar cómo construyes el proyecto desde cero, usando herramientas locales y conectando a GitHub.

MODELO DE RAMAS
main
  │
  └── develop
       ├── feature/setup-project

release/1.0.0 → main

3.1 Inicializar Proyecto Independiente

Construirás tu propia versión del sistema desde cero. Empieza creando tu carpeta y configurando Git de manera local. 

# Crea la carpeta del proyecto
mkdir LibraryApp_NombreApellido

# Entra a la carpeta
cd LibraryApp_NombreApellido

# Inicializa el control de versiones vacío
git init

3.2 Crear y vincular repositorio en GitHub con GitHub CLI

Utiliza gh (GitHub CLI) para crear el proyecto remoto en tu cuenta y enlazado automáticamente a tu directorio de trabajo local. 

# Crea el repositorio privado en tu GitHub indicando como fuente el directorio actual (.)
gh repo create LibraryApp_NombreApellido --private --source=. --remote=origin
¿Qué hace este comando? Genera el repositorio vacío en la nube, agrega el remote llamado origin a tu Git local, y te permite hacer push en los siguientes pasos sin tener que usar el navegador.

3.3 Inicializar Git Flow

Una vez vinculado, inicializa la estructura de ramas. Deja todas las opciones por defecto (presionando Enter). 

# Crea las ramas base (main y develop) y configura los prefijos
git flow init

# Verifica que te encuentras en develop
git status

3.4 Convención de commits

El mensaje debe explicar qué cambió y, de ser posible, en qué capa ocurrió. 

feat(model): agregar clase Libro
feat(dao): implementar LibroDAO
feat(ui): crear formulario de libros
docs(javadoc): documentar LibroDAOImpl
docs(glosario): agregar concepto JDBC
