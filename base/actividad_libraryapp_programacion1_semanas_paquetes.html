Aprende a leer, analizar, documentar y reconstruir una aplicación JavaFX utilizando MVC + DAO + MySQL + JDBC + FXML + SceneBuilder. El proyecto terminado es una referencia de ingeniería: tu objetivo no es copiarlo, sino descubrir cómo está construido y reproducir su arquitectura paso a paso.

Configuración del Proyecto con Librerías

Gestión manual de dependencias (.jar)

En esta modalidad de trabajo, la gestión de dependencias externas (Driver JDBC de MySQL y SDK de JavaFX) se realiza incorporando físicamente los archivos binarios .jar en el directorio del proyecto y configurándolos manualmente en el IDE y en las instrucciones de compilación/ejecución.

folder_zip Estructura física del directorio `lib/`

Crea una carpeta llamada lib en la raíz del proyecto e incluye los siguientes conectores y módulos:

LibraryApp/
├── lib/
│   ├── mysql-connector-j-8.3.0.jar        # Driver JDBC de MySQL
│   ├── javafx.base.jar                    # JavaFX Base Module
│   ├── javafx.controls.jar                # JavaFX UI Controls
│   ├── javafx.fxml.jar                    # JavaFX FXML Loader
│   └── javafx.graphics.jar                # JavaFX Graphics
│   └── javafx.media.jar                   # JavaFX Medios
│   └── javafx.swing.jar                   # JavaFX Componentes Swing
│   └── javafx.web.jar                     # JavaFX Elemenots Web
├── src/                                   # Código fuente Java (.java)
└── bin/                                   # Bytecode compilado (.class)

settings Instrucciones de configuración en IDEs principales

En NetBeans IDE: 1. Clic derecho en el proyecto > Properties > Libraries.
2. En la pestaña Classpath, haz clic en Add JAR/Folder.
3. Navega a la carpeta lib/, selecciona todos los archivos .jar y presiona Open.
4. En la pestaña Run, añade los VM Options para JavaFX: --module-path "C:\javafx-sdk-21.0.11\lib" --add-modules javafx.controls,javafx.fxml

terminal Compilación y Ejecución manual por Línea de Comandos (CLI) si es necesario

Si compilas directamente desde la terminal, utiliza las siguientes instrucciones especificando el classpath y los módulos de JavaFX:

1. Compilación: 
javac -cp "lib/*" --module-path lib --add-modules javafx.controls,javafx.fxml -d bin src/org/ac/model/*.java src/org/ac/dao/*.java src/org/ac/controller/*.java
2. Ejecución: 
java -cp "bin:lib/*" --module-path lib --add-modules javafx.controls,javafx.fxml org.ac.Main

3.1 Inicializar Proyecto Independiente

Construirás tu propia versión del sistema desde cero. Empieza creando tu carpeta y configurando Git de manera local. 

# Crea la carpeta del proyecto
mkdir LibraryApp_NombreApellido

# Entra a la carpeta
cd LibraryApp_NombreApellido

# Inicializa el control de versiones vacío
git init

3.2 Crear y vincular repositorio en GitHub con GitHub CLI

Utiliza gh (GitHub CLI) para crear el proyecto remoto en tu cuenta y enlazado automáticamente a tu directorio de trabajo local. 

# Crea el repositorio privado en tu GitHub indicando como fuente el directorio actual (.)
gh repo create LibraryApp_NombreApellido --private --source=. --remote=origin
¿Qué hace este comando? Genera el repositorio vacío en la nube, agrega el remote llamado origin a tu Git local, y te permite hacer push en los siguientes pasos sin tener que usar el navegador.

3.3 Inicializar Git Flow

Una vez vinculado, inicializa la estructura de ramas. Deja todas las opciones por defecto (presionando Enter). 

# Crea las ramas base (main y develop) y configura los prefijos
git flow init

# Verifica que te encuentras en develop
git status

Guía Javadoc: Etiquetas Principales y Ejemplos Prácticos

Estándar profesional de documentación formal dentro del código Java.

Javadoc es la herramienta estándar para generar documentación en formato HTML directamente desde los comentarios del código fuente. Todo el código reconstruido en LibraryApp debe incluir Javadoc en nivel de clase, interfaz, atributos y métodos públicos.

Etiqueta Javadoc Aplica a Descripción / Propósito
@author Clase, Interfaz Indica el nombre del desarrollador o autor que creó/mantiene el componente.
@version Clase, Interfaz Define la versión actual del módulo (ej. 1.0.0).
@param <nombre> Métodos, Constructores Describe el propósito de un parámetro de entrada y sus restricciones o formato esperado.
@return Métodos (non-void) Explica el valor de retorno que produce el método tras su ejecución exitosa.
@throws / @exception Métodos, Constructores Documenta las excepciones explícitas que el método puede lanzar bajo condiciones erróneas.
@see General Añade una referencia cruzada a otra clase, método o enlace relevante.
// EJEMPLO PRÁCTICO DE JAVADOC PROFESIONAL
package org.ac.dao;

import org.ac.model.Libro;
import java.util.List;

/**
 * Contrato DAO que define las operaciones de persistencia CRUD
 * para la entidad {@link Libro} dentro del sistema LibraryApp.
 * 
 * @author Nombre del Estudiante
 * @version 1.0.0
 * @see org.ac.model.Libro
 */
public interface LibroDAO {

    /**
     * Registra un nuevo libro en la base de datos MySQL mediante un procedimiento almacenado.
     * 
     * @param libro Objeto {@link Libro} que contiene los datos a registrar. No debe ser null.
     * @return {@code true} si la inserción fue exitosa; {@code false} en caso contrario.
     * @throws IllegalArgumentException si el parámetro libro contiene datos inválidos o vacíos.
     * @throws RuntimeException si ocurre un error de conexión con JDBC o la base de datos.
     */
    boolean insertar(Libro libro);

    /**
     * Recupera el listado completo de libros registrados en la librería.
     * 
     * @return Una lista de tipo {@link List} que contiene los objetos {@link Libro}.
     *         Retorna una lista vacía si no existen registros en la base de datos.
     */
    List<Libro> listar();
}
